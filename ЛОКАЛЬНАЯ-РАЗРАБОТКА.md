# Локальная разработка Локсо (macOS)

Проверенная инструкция по запуску проекта на своём компьютере. Проект — монорепозиторий (pnpm): фронтенды на React Router + Vite, бэкенд на Django, вспомогательные сервисы.

## Что понадобится

- **Docker Desktop** — для инфраструктуры (PostgreSQL, Redis/Valkey, RabbitMQ, MinIO). [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop)
- **Node.js ≥ 22.18** и **pnpm 11** — фронтенды. Проще всего через `nvm`:
  `nvm install 22 && npm install -g pnpm@11`
- **Python 3.10+** — бэкенд (в macOS обычно уже есть; проверить `python3 --version`).

Проверить версии: `node -v`, `pnpm -v`, `python3 --version`, `docker --version`.

---

## Рекомендуемый режим: гибридный

Инфраструктура (БД, кеш, очередь, файлы) — в Docker; фронтенд — нативно, чтобы работал hot-reload. Бэкенд по умолчанию тоже удобнее поднимать в Docker — так он работает сразу, без правки конфигурации (см. Шаг 4, вариант A). Нативный запуск бэкенда (вариант B) даёт hot-reload и дебагер, но требует осознанно поменять адреса зависимостей в `apps/api/.env`, потому что как есть они указывают на Docker-хосты.

### Шаг 1. Env-файлы

Из корня репозитория:

```bash
./setup.sh
```

Скрипт создаст `.env` во всех приложениях из `*.env.example`. При необходимости откройте `apps/api/.env` и проверьте строки подключения (значения по умолчанию рассчитаны на локальный Docker).

### Шаг 2. Поднять инфраструктуру в Docker

```bash
docker compose -f docker-compose-local.yml up -d plane-db plane-redis plane-mq plane-minio
```

Поднимутся четыре контейнера: PostgreSQL (5432), Valkey/Redis (6379), RabbitMQ (порт наружу не публикуется, доступен только другим контейнерам), MinIO (9000). Проверить: `docker compose -f docker-compose-local.yml ps`.

### Шаг 3. Установить зависимости

```bash
pnpm install
```

Ставит зависимости всего монорепозитория (первый раз ~1–2 минуты).

### Шаг 4. Бэкенд (Django API)

Как поставляется, `apps/api/.env` указывает на Docker-хосты (`POSTGRES_HOST="plane-db"`, `REDIS_HOST="plane-redis"`, `RABBITMQ_HOST="plane-mq"`, `AWS_S3_ENDPOINT_URL="http://plane-minio:9000"`), которые не резолвятся с хост-машины. Поэтому нативный запуск без правки конфигурации не работает.

**Вариант A — Docker (по умолчанию, работает из коробки).** Добавьте `migrator api worker beat-worker` к команде `up` из Шага 2:

```bash
docker compose -f docker-compose-local.yml up -d plane-db plane-redis plane-mq plane-minio migrator api worker beat-worker
```

`migrator` — отдельный сервис, который применяет миграции; без него `api` зависает в ожидании миграций и никогда не поднимется. Проверка: `curl http://localhost:8000/` → `{"status": "OK"}`.

**Вариант B — нативно**, для hot-reload и дебагера. Требует осознанно поменять адреса зависимостей — не делайте это автоматически:

1. В `apps/api/.env` замените `POSTGRES_HOST`, `REDIS_HOST`, `RABBITMQ_HOST` на `localhost`, а `AWS_S3_ENDPOINT_URL` — на `http://localhost:9000`.
2. Добавьте публикацию порта для `plane-mq` в `docker-compose-local.yml` (например, `5672:5672`) — у Postgres, Redis и MinIO порты уже опубликованы, у RabbitMQ по умолчанию нет.

Затем, в отдельной вкладке терминала:

```bash
cd apps/api
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements/local.txt
# Загрузить переменные окружения из .env (Django сам их не читает):
set -a && source .env && set +a
python manage.py migrate
python manage.py runserver 8000
```

API поднимется на `http://localhost:8000`. Проверка: `curl http://localhost:8000/` → `{"status": "OK"}` — это проверяет только сам Django и проходит даже если RabbitMQ недоступен.

**Фоновые задачи (уведомления, импорт, экспорт)** — при необходимости в ещё одной вкладке (та же venv, тот же `source .env`; требует полной правки хостов из варианта B, включая RabbitMQ, — либо используйте вариант A):

```bash
celery -A plane worker -l info
```

### Шаг 5. Фронтенд

Сначала один раз собрать внутренние пакеты, затем запустить dev-сервер:

```bash
# из корня репозитория
pnpm turbo run build --filter='web^...'   # сборка пакетов, от которых зависит web
pnpm --filter web dev                      # http://localhost:3000
```

Откройте `http://localhost:3000`. Первый пользователь регистрируется через email+пароль (вход через Яндекс/VK требует ключей — см. ниже).

Аналогично при необходимости запускаются `space` (публичные страницы) и `admin` (админ-панель инстанса):
`pnpm --filter admin dev`, `pnpm --filter space dev`.

## Альтернатива: всё в Docker

Быстро поднять весь стек без нативной установки Node/Python:

```bash
./setup.sh
docker compose -f docker-compose-local.yml up -d
```

Поднимутся все сервисы, включая api/worker/beat/migrator в контейнерах. Удобно «просто посмотреть, как работает», но для активной разработки хуже: нет мгновенного hot-reload, дольше пересборка. Логи: `docker compose -f docker-compose-local.yml logs -f api`.

## Настройка входа через Яндекс ID / VK ID (опционально)

Провайдеры уже встроены, но нужны ключи из кабинетов:

- **Яндекс:** создать приложение на [oauth.yandex.ru](https://oauth.yandex.ru), redirect URI `http://localhost:8000/auth/yandex/callback/`, доступы `login:email`, `login:info`, `login:avatar`.
- **VK ID:** приложение на [id.vk.com/about/business](https://id.vk.com/about/business), redirect URI `http://localhost:8000/auth/vk/callback/`.

Затем в админ-панели (`pnpm --filter admin dev`, раздел Authentication) ввести Client ID/Secret и включить провайдер. Аналогично раздел AI — для пресетов YandexGPT/GigaChat.

## Частые проблемы

- **`django.db.utils.OperationalError` (ошибка резолва хоста) при migrate** — почти всегда значит, что бэкенд запущен нативно (вариант B) без правки хостов в `apps/api/.env`: `POSTGRES_HOST=plane-db` не резолвится с хост-машины. Исправление — Шаг 4, вариант B, пункт 1 (или используйте вариант A).
- **`Failed to resolve entry for "@plane/..."` при запуске web** — не собраны внутренние пакеты. Выполните `pnpm turbo run build --filter='web^...'`.
- **Переменные окружения не подхватываются** — Django не читает `.env` сам; перед `manage.py` выполните `set -a && source .env && set +a` (в рамках активной сессии терминала).
- **Порт занят** — dev-сервер web можно запустить на другом порту: `pnpm --filter web dev -- --port 3001`.
- **Загрузка обложки проекта или вложения падает, а в сети виден запрос на `localhost:8000/uploads`** — в `apps/api/.env` не задана `MINIO_PUBLIC_ENDPOINT_URL`. В продакшене перед API и MinIO стоит прокси и адреса совпадают, локально прокси нет — пропишите `MINIO_PUBLIC_ENDPOINT_URL="http://localhost:9000"`.

## Ежедневный цикл

1. `docker compose -f docker-compose-local.yml up -d plane-db plane-redis plane-mq plane-minio migrator api worker beat-worker` (вариант A из Шага 4; для нативного бэкенда — вариант B)
2. Вкладка: `pnpm --filter web dev`
3. Работа в `http://localhost:3000`. Перед коммитом: `pnpm --filter web check:types` и `pnpm --filter web check:lint`.

Полезное: миграции после изменения моделей — `python manage.py makemigrations && python manage.py migrate`. Прогон тестов бэкенда — изолированный Docker-стек: `docker compose -f docker-compose-test.yml run --rm api-tests pytest -m unit` (см. `CONTRIBUTING.md`).
